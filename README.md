# ALEPH T08 — Passkey Portfolio

기존 T01 소개 페이지에 패스키 인증과 계정별 비공개 공간을 추가한 포트폴리오입니다.

공개 소개는 누구나 볼 수 있으며, 비공개 정보는 기존에 등록한 패스키로 인증한 뒤 확인할 수 있습니다. 별도의 회원가입 화면이나 비밀번호 입력란은 제공하지 않습니다.

- [배포 사이트](https://alepht08passkeyportfolio.vercel.app/)
- [GitHub 저장소](https://github.com/sumin003/ALEPH_T08_Passkey_Portfolio)

## 1. 주요 기능

### 공개 소개

기존 소개, 경험, 목표를 유지하고 다음 공개정보를 표시합니다.

- 이메일
- GitHub 주소
- 전공·학력

### 비공개 공간

패스키로 인증하면 본인 계정에 속한 다음 항목을 확인할 수 있습니다.

- 준비 중인 프로젝트 메모
- 개인 목표와 진행 상황
- 스스로 쓰는 회고

비공개 본문에는 검증을 위해 만든 가상 내용을 넣었습니다. 검증용 A·B 계정에는 서로 다른 내용을 넣어 계정별 접근 제한을 확인했습니다. 실제 개인정보는 포함하지 않았으며, 본문 작성·편집 기능은 제공하지 않습니다.

인증 전에는 비공개 내용을 화면에 표시하지 않습니다. 비공개 본문은 공개 HTML이나 JavaScript 파일에 포함하지 않고, 인증된 요청에만 서버에서 반환합니다.

### 패스키 등록·관리

최초 패스키 등록은 종료했습니다. 인증 전에는 등록·관리 화면이 숨겨지며, 서버에서도 신규 계정의 등록 요청을 거절합니다.

기존 패스키로 인증한 뒤에는 다음 기능을 사용할 수 있습니다.

- 같은 계정에 백업 패스키 추가 등록
- 패스키 이름·저장 위치 메모·등록 날짜 확인
- 패스키 삭제
- 남은 패스키로 다시 인증

마지막 패스키는 삭제할 수 없도록 제한하고, 다른 패스키를 먼저 등록하라는 안내를 표시합니다.

사이트에서 패스키를 삭제하면 서버에 등록된 공개키를 제거하고 해당 계정의 기존 세션을 폐기합니다. 기기나 패스키 관리자에 저장된 패스키는 사용자가 해당 기기·관리자에서 관리합니다.

## 2. 사용 방법

1. 배포 사이트에서 공개 소개를 확인합니다.
2. 비공개 공간의 패스키 로그인 버튼을 누르고, 기존 패스키로 본인 확인을 진행합니다.
3. 비공개 내용을 확인한 뒤 로그아웃합니다.

백업 패스키를 추가하려면 먼저 기존 패스키로 인증한 다음, 등록·관리 화면에서 패스키 이름과 실제 저장할 기기·관리자를 입력합니다.

입력한 패스키 이름은 등록 목록과 새 패스키의 인증 창에 사용할 이름으로 전달됩니다. 인증 창의 실제 표시는 기기나 패스키 관리자에 따라 다를 수 있습니다. 저장 위치는 사용자가 실제 선택한 위치를 기록하는 메모입니다.

인증 질문은 서버에서 자동으로 생성하고 브라우저와 기기가 처리하므로 사용자가 직접 답을 입력하지 않습니다. Windows Hello PIN이나 휴대폰 잠금 해제 값은 기기의 인증 창에서 처리하며, 사이트는 이 값을 받거나 저장하지 않습니다.

## 3. 사용 기술과 선택 이유

- HTML, CSS, JavaScript
- Node.js 24
- Vercel Functions
- SimpleWebAuthn Server 14.0.3
- Supabase Postgres

기존 소개 페이지를 유지하면서 패스키 검증과 비공개 자료 접근을 서버에서 처리하도록 구성했습니다.

WebAuthn 옵션 생성과 등록 응답·인증 서명 검증에는 SimpleWebAuthn을 사용했습니다. 공개키 기반 검증을 라이브러리로 처리하고, 등록 제한·일회용 질문 보관·세션 관리·자료 소유자 검사·화면 동작은 프로젝트 코드에서 구현했습니다.

## 4. 인증 처리 흐름

| 기능 | 처리 흐름 |
|---|---|
| 패스키 추가 등록 | 기존 인증 상태 확인 → 서버 질문 생성 → 기기에서 패스키 생성 → 서버 검증 → 공개키 저장 |
| 패스키 인증 | 서버 질문 생성 → 기기에서 개인키로 서명 → 서버가 공개키로 검증 → 세션 발급 |
| 비공개 조회 | 세션 유효성 확인 → 인증된 계정의 자료만 조회 |
| 로그아웃 | 서버 세션 폐기 → 쿠키 만료 → 비공개 내용과 관리 화면 숨김 |
| 패스키 삭제 | 인증 상태·소유자·남은 패스키 수 확인 → 공개키 삭제 → 기존 세션 폐기 |

서버에는 공개키와 패스키 식별 정보를 저장합니다. 개인키는 인증 기기나 패스키 관리자에서 관리하며 서버로 전송하지 않습니다.

등록과 인증에 사용하는 질문은 일회용입니다. 서버는 질문을 보관하고, 사용 여부와 만료 시간을 확인한 뒤 응답을 처리합니다.

인증 상태는 HttpOnly 쿠키와 서버 세션으로 유지합니다. 비공개 자료의 소유자는 서버 세션을 기준으로 판단합니다. URL에 다른 계정의 식별값을 넣은 조회 요청은 거절하고, 요청 본문에 넣은 계정값은 자료 소유자를 결정하는 데 사용하지 않습니다.

## 6. 직접 확인한 결과

### 공개·비공개 화면

- 로그아웃 상태에서도 공개 소개 페이지가 표시됩니다.
- 인증 전에는 비공개 내용과 패스키 등록·관리 화면이 보이지 않습니다.
- 기존 패스키로 인증하면 본인의 비공개 내용과 패스키 관리 화면이 표시됩니다.
- 로그아웃하면 비공개 내용과 패스키 관리 화면이 다시 숨겨집니다.

### 등록·인증

- 실제 기기에서 패스키 등록과 인증을 확인했습니다.
- 등록이 끝난 뒤 서버에 공개키가 저장된 것을 확인했습니다.
- DB에서 확인한 등록 질문 2개가 서로 달랐습니다.
- DB에서 확인한 인증 질문 5개가 서로 달랐습니다.
- 패스키 추가 등록·삭제와 삭제 후 남은 패스키를 이용한 인증을 확인했습니다.

### 계정별 접근 제한

검증용 A·B 계정에 서로 다른 비공개 내용을 넣고, 실제 배포 사이트에서 각 계정으로 인증하여 확인했습니다.

| 요청 | 확인 결과 |
|---|---|
| A 계정으로 A 자료 조회 | A의 비공개 내용 표시 |
| B 계정으로 B 자료 조회 | B의 비공개 내용 표시 |
| A 계정으로 B 자료 요청 | `403`, B의 비공개 내용 반환 없음 |
| B 계정으로 A 자료 요청 | `403`, A의 비공개 내용 반환 없음 |

## 7. 실행

Node.js 24 환경에서 다음 명령어를 실행합니다.

```bash
npm install --ignore-scripts
npm run build
npm run dev
```

실제 패스키 인증은 정식 HTTPS 배포 주소에서 확인합니다. 현재 배포에서는 최초 등록이 닫혀 있으므로 기존에 등록된 패스키를 사용해야 합니다.
