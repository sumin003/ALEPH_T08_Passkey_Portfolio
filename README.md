# ALEPH T08 — Passkey Portfolio

기존 T01 소개 페이지에 패스키 등록·로그인과 사용자별 비공개 영역을 추가한 포트폴리오입니다.
공개 소개는 누구나 볼 수 있으며, 비공개 정보는 패스키로 로그인한 뒤 확인할 수 있습니다.

- 배포 주소: https://alepht08passkeyportfolio.vercel.app/
- GitHub: https://github.com/sumin003/ALEPH_T08_Passkey_Portfolio

## 주요 기능

### 공개 소개

기존 소개, 경험, 목표를 유지하고 다음 공개정보를 표시합니다.

- 이메일
- GitHub 주소
- 전공·학력

### 비공개 영역

패스키 로그인 후 본인에게 속한 다음 항목을 조회합니다.

- 준비 중인 프로젝트 메모
- 개인 목표와 진행 상황
- 스스로 쓰는 회고

현재 비공개 본문은 비어 있으며, 본문 작성·편집 기능은 제공하지 않습니다.
로그인하지 않았거나 세션이 만료된 경우 비공개 자료 요청을 거절합니다.

### 패스키 관리

- 첫 패스키 등록
- 로그인한 계정에 패스키 추가 등록
- 패스키 이름·저장 위치 메모·등록 날짜 표시
- 패스키 삭제 및 마지막 패스키 삭제 차단
- 삭제 후 남은 패스키로 재로그인

사이트에서 패스키를 삭제하면 서버에 등록된 공개키를 제거하고 해당 계정의 기존 세션을 폐기합니다.
기기나 패스키 관리자에 저장된 패스키를 원격으로 삭제하지는 않습니다.

## 사용 방법

1. 정식 배포 주소에서 패스키 이름과 실제 저장할 기기·관리자를 입력하고 등록합니다.
2. 패스키로 로그인하여 비공개 영역을 확인합니다.
3. 사용 후 로그아웃합니다.

패스키 이름과 저장 위치는 목록을 구분하기 위한 표시 정보입니다.
인증 질문은 서버에서 자동 생성하므로 사용자가 입력하지 않습니다.
Windows Hello PIN이나 휴대폰 잠금 해제 값은 기기의 인증 창에서만 입력하며 사이트는 이 값을 받지 않습니다.

기존 계정에 패스키를 추가하려면 먼저 로그인해야 합니다.
로그인하지 않은 별도 환경에서 첫 등록을 하면 새 계정이 만들어집니다.

## 사용 기술

- HTML, CSS, JavaScript
- Node.js 24
- Vercel Functions
- @simplewebauthn/server 14.0.3
- Supabase Postgres

기존 소개 페이지를 유지하면서 패스키 검증과 비공개 자료 접근을 서버에서 처리하도록 구성했습니다.
WebAuthn 옵션 생성과 등록 응답·로그인 서명 검증에는 SimpleWebAuthn을 사용합니다.
등록·로그인 API, 일회용 질문 처리, 서버 세션, 소유자 검사와 화면 동작은 직접 구현했습니다.

## 인증 흐름

| 기능 | 처리 흐름 |
| --- | --- |
| 등록 | 서버 질문 생성 → 기기에서 패스키 생성 → 서버 검증 → 공개키 등록 |
| 로그인 | 서버 질문 생성 → 기기에서 서명 → 서버가 저장된 공개키로 검증 → 세션 발급 |
| 비공개 조회 | 세션 유효성 확인 → 로그인한 사용자의 자료만 조회 |
| 로그아웃 | 서버 세션 폐기 → 쿠키 만료 → 비공개 화면 잠금 |

등록과 로그인 질문은 일회용이며, 이미 사용했거나 만료된 질문은 거절합니다.
로그인은 HttpOnly 쿠키와 서버 세션으로 유지합니다.
비공개 조회의 소유자는 요청에 입력된 계정 값이 아니라 서버 세션을 기준으로 판단합니다.

## 검증

- 자동 테스트 32개 통과
- 계정별 조회와 요청 변조 등을 확인하는 로컬 요청 검사 11개 통과
- 실제 DB에서 가상 계정·자료를 이용한 트랜잭션 검사 후 롤백
- 사용자가 실제 패스키 등록·로그인·추가·삭제와 남은 패스키 로그인 동작 확인

자동 테스트의 WebAuthn 검증기는 테스트 대역이며, 로컬 검사 결과는 실제 기기 인증이나 배포 요청·응답 기록을 대신하지 않습니다.

## 실행

Node.js 24 환경에서 다음 명령어를 실행합니다.

```bash
npm install --ignore-scripts
npm test
npm run verify:card5
npm run build
npm run dev
```

실제 패스키 등록·로그인은 정식 HTTPS 배포 주소에서 확인합니다.

## 짧은 확인 방법

- 어디로 가나요: https://alepht08passkeyportfolio.vercel.app/
- 무엇을 하나요: ① 공개 소개와 잠긴 영역 확인 ② 패스키 로그인 ③ 로그아웃
- 무엇이 보이면 통과인가요: 공개 소개는 계속 보이고, 비공개 항목은 인증 후에만 열리며 로그아웃 후 조회는 거절됩니다.
- 안 될 때 무엇이 보이나요: 정상 인증 후에도 비공개 영역이 열리지 않거나, 비로그인·다른 계정 상태에서 비공개 자료가 반환됩니다.

## AI와 나

- AI에게 맡긴 일: 패스키 인증과 서버 접근 제어 구현, 자동 검사와 문서 초안 작성.
- 내가 판단한 일: 공개·비공개 항목, 디자인, 본문을 비워 두는 방식과 실제 기기에서의 기능 검증.
- AI 제안을 그대로 따르지 않은 일: 색상과 배치 제안을 원하는 디자인에 맞게 수정하도록 요청함.
