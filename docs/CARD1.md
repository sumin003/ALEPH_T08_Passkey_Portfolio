# T08 카드 1 — 공개·비공개 경계

> 아래는 카드 1 당시의 기록입니다. 현재 카드 2의 DB 구조와 등록 코드는 CARD2.md를 참고하세요.

## 이번 구현의 범위

- 첨부받은 index.html, style.css, script.js를 기준으로 구현했다.
- 공개정보는 이메일, GitHub 주소, 전공·학력을 한 칸에 표시한다.
- 비공개 칸에는 잠김 안내만 표시한다. 비공개 항목을 HTML에 미리 숨기지 않는다.
- 서버 전용 `server/private-items.mjs`에 합의한 제목 3개를 둔다.
  - 준비 중인 프로젝트 메모
  - 개인 목표와 진행 상황
  - 스스로 쓰는 회고
- 본문은 사용자가 아직 정하지 않았으므로 모두 빈 문자열이다. 실제 개인 기록은 없다.

## 서버 접근 차단

`/api/private-info`는 카드 1 단계에서 모든 요청을 401로 거절한다.
쿠키, Authorization 헤더, 계정 ID, loggedIn 쿼리를 보내도 통과하지 않는다.
이것은 실제 패스키 로그인 구현이 아니다. 카드 2·3에서 등록·서명 검증·서버 세션을
구현한 뒤, 검증한 세션의 소유자 자료만 조회하는 경로로 확장해야 한다.
현재는 로그인 성공 경로, 계정별 저장, 편집·저장 기능이 없으며 DB도 연결하지 않았다.

응답 본문:

```json
{"error":"AUTH_REQUIRED","message":"비공개 정보는 패스키 로그인 후 확인할 수 있습니다."}
```

응답에는 `Cache-Control: private, no-store, max-age=0`를 붙인다.
HEAD 요청에는 401 상태와 헤더만 보내고 본문을 넣지 않는다.
브라우저는 실제 API 응답을 확인한다. 연결 오류와 정상적인 401 차단을 구분해 안내하며,
응답 본문을 화면에 삽입하지 않는다.

## 정적 파일 노출 방지

`npm run build`는 index.html, style.css, script.js, images/만 dist/에 복사한다.
Vercel은 dist/를 공개 파일로 배포하고 api/private-info.js는 서버 함수로 실행한다.
서버 전용 항목 파일은 함수 번들에만 포함한다.
server/, docs/, tests/, 환경 파일, package.json을 정적 공개 폴더로 복사하지 않는다.
GitHub 소스는 공개이므로 실제 개인정보나 비밀값은 서버 소스에도 적지 않는다.
실제 개인 기록을 추가할 단계에서는 서버 DB에 저장해야 한다.

## 배포 후 확인 방법

1. 시크릿 창에서 공개 페이지를 연다. 공개정보가 보이고 비공개 칸에는 잠김 안내만 보여야 한다.
2. 개발자 도구 Network에서 `/api/private-info`의 상태 401과 응답 본문을 확인한다.
3. `/server/private-items.mjs`를 직접 열어 원본 코드가 내려오지 않는지 확인한다.
4. 페이지 소스와 내려받은 script.js에 비공개 항목의 제목·본문이 없는지 확인한다.

서버 조회가 없는 file:// 열기나 일반 정적 Live Server만으로는 API 차단을 검사할 수 없다.
