# 카드 4 — 패스키 추가 등록과 삭제

## 목표와 순서

같은 계정에 패스키 2개를 등록하고 목록의 이름·날짜를 확인한다. 하나를 삭제한 뒤 남은 패스키로 다시 로그인한다.
삭제한 패스키로 새 로그인은 거절되어야 한다. 마지막 패스키가 없어지는 경우도 화면과 문서에 설명한다.

1. 기존 패스키로 로그인한다.
2. 패스키 관리 칸에 두 번째 이름과 저장 위치를 입력하고 추가 등록한다.
3. 같은 계정의 패스키 2개가 이름·날짜와 함께 표시되는지 확인한다.
4. 하나를 삭제한다. 현재 구현은 본인 계정의 기존 로그인 세션도 모두 폐기하여 재로그인을 요구한다.
5. 남은 패스키로 로그인에 성공하고, 삭제한 패스키로는 거절되는 기록을 남긴다.

## 구현

- 로그인 세션의 user_id와 기존 webauthn_user_id를 재사용하여 같은 계정에 추가한다. 사용자 ID를 입력받지 않는다.
- 기존 credential ID를 excludeCredentials로 전달해 동일 패스키의 중복 등록을 막는다.
- 추가 등록 질문을 로그인 세션과 브라우저 바인딩 쿠키에 함께 묶는다.
- 추가 등록 도중 로그아웃하거나 다른 세션으로 바뀌면 저장을 거절한다.
- 등록 응답의 challenge·Origin·RP ID·사용자 확인은 기존 SimpleWebAuthn 검증을 그대로 적용한다.
- 공개키만 저장하며 개인키와 Windows Hello PIN은 사이트에 전송하지 않는다.
- 목록에 credential_id, 이름, 저장 위치, 등록 시각을 반환한다. 공개키 원문은 목록에 반환하지 않는다.
- 삭제는 로그인한 사용자의 credential만 가능하다. 다른 계정의 credential ID는 404이며 삭제되지 않는다.
- 서버 DB에서 잠금을 잡고 개수를 검사하므로, 클라이언트 버튼을 우회해도 마지막 1개는 삭제할 수 없다.
- 삭제된 서버 공개키는 더 이상 로그인 검증에 사용되지 않는다.
- 같은 사용자에 대한 추가·삭제는 같은 트랜잭션 잠금으로 직렬화한다.
- 삭제는 사이트에 등록된 공개키를 제거한다. Windows Hello/휴대폰/관리자의 개인키를 원격으로 삭제하지 않는다.

## 마지막 패스키와 0개 처리

화면에 '등록된 패스키가 없으면 로그인할 수 없습니다. 마지막 패스키는 삭제할 수 없으니 다른 패스키를 먼저 등록해 주세요.'를 표시한다.
1개만 남으면 삭제 버튼을 비활성화하며, 직접 API 요청을 보내도 LAST_PASSKEY / 409로 거절한다.
관리자 작업 등으로 모든 패스키가 외부에서 지워지면 기존 계정으로 새 로그인할 수 없다. 이 과제 범위에는 별도 복구 수단이 없다.
새 계정의 첫 등록으로 기존 계정의 자료가 복구되는 것은 아니다.

## 관리 정보와 PIN의 구분

- 이름과 저장 위치 입력은 사람이 목록을 구분하기 위한 표시 정보다. 인증 질문(challenge)이 아니다.
- challenge는 요청마다 서버가 자동 생성해 DB에 보관한다.
- PIN은 사이트 비밀번호가 아니다. Windows 보안 창에서 기기의 패스키를 사용하도록 잠금을 풀 때 입력하며 사이트는 서명만 받는다.
- 실제 저장 위치는 사용자가 선택한 관리자와 입력 메모가 일치하는지 확인한다. 사이트는 저장 관리자를 자동 판별하지 않는다.

## DB 변경

- t08_challenges에 existing_user_id와 registration_session_hash 추가
- t08_finish_additional_registration 추가: 기존 계정의 추가 키 검증 후 저장
- t08_remove_passkey 추가: 소유자 검사, 마지막 키 보호, 삭제와 세션 폐기

기존 등록 패스키와 개인 자료는 삭제하지 않았다. SQL은 이미 적용했으므로 card4-schema.sql을 재실행하지 않는다.
두 함수는 SECURITY INVOKER이며 PUBLIC/anon/authenticated 실행 권한을 제거했다. service_role만 실행한다.

## 검사

- 기존 포함 Node 자동 검사 28개 통과. 암호 검증기는 자동 테스트에서 모킹되어 있다.
- 실제 DB 트랜잭션에서 두 번째 키의 동일 소유자 저장, 마지막 키 삭제 차단, 2개 중 하나 삭제, 세션 폐기, 삭제 키 로그인 거절, 남은 키 로그인 처리를 검사하고 ROLLBACK했다.
- 실제 사용자 키를 삭제한 테스트가 아니다. 실제 기기에서 성공·실패를 확인한 증거로 주장하지 않는다.

| 기준 | 구현 | 실제 제출 증거 |
| --- | --- | --- |
| C42 | 같은 계정에 여러 credential 저장 | 실제 패스키 2개 등록 후 DB/목록 확인 필요 |
| C43 | 목록 이름·등록 날짜 표시 | 목록 화면 캡처 필요 |
| C44 | 삭제 후 남은 키 로그인 경로 유지 | 남은 키 실제 로그인 성공 요청·응답 필요 |
| C45 | 삭제된 credential 조회 시 로그인 거절 | 삭제한 키 실제 로그인 실패 요청·응답 필요 |
| C46 | 마지막 키 삭제 차단·0개 시 로그인 불가 안내 | 화면 안내·서버 409 기록 준비 |

배포 후 다른 기기나 다른 저장 관리자에 두 번째 패스키를 등록한다. 같은 Windows Hello 저장소를 사용하는 다른 브라우저는 별도의 백업이 아닐 수 있다.
Network 기록의 쿠키·토큰은 제출 전에 마스킹한다. 기존 비공개 본문은 아직 비어 있다.
